## 2. 效果层面（“用起来怎样”）

| 维度 | 期望 | 现状 → 0.4.0 |
|---|---|---|
| 精度 | 剪辑点落在帧上 | 面板秒级按钮，可能落在帧间 → MCP 全部对齐到序列帧格 |
| 可预期 | 先看再做 | 无 → 每个写工具 `dry_run`，返回将执行的引擎命令 |
| 可验证 | 做完知道改了什么 | 面板只刷新列表 → MCP 返回 before/after diff（哪些片段动了、时长变化） |
| 原子性 | 一步要么全成要么全不成 | `run --keep-going` 会留下半个操作（比如互换只动了一个）→ 默认失败回滚 |
| 响应 | 不卡宿主 | 编辑用 spawnSync 会阻塞宿主（已知）；MCP 是独立进程，不阻塞 DSH |
| 长任务 | 进度可信 | 宿主重启后任务永远“进行中” → 0.4.0 按 pid 存活判定，进程不在就结算 |

## 3. 前端界面（344 px 侧栏）

做得好的（0.3.1）：主题跟随宿主、单层分隔线、三态按钮、焦点环、减弱动效、标签不换行。

剪辑角度的主要缺口，按价值排序：

1. **没有时间线视图**。片段是一列文字，看不出长短、空隙、音视频对应。建议：一条迷你时间线（V1/A1 两行色块，宽度 ∝ 时长，空隙和重叠标红），点色块即选中。344 px 下仍然可读。
2. **修剪粒度太粗**。只有 ±0.5/1/3 秒。建议：加“帧”步进（±1f、±5f）和一个可输入时间码的框；显示片段的入点/出点时间码，而不只是时长。
3. **没有“在这里切开”**。预览里已经有片段内的拖动条（scrub），正好可作播放头 —— 在那个位置加“分割”按钮即可，接 `timeline.razor`（先在真引擎核对参数）。
4. **排序只能和邻居换**。长片子要点很多次。建议：上下拖拽或“移到第 N 位”，后端已有 `reorder` 逻辑可复用。
5. **没有质检提示**。把 `check_timeline` 的结果做成剪辑页顶部的一行徽标（“2 处黑场 · 1 处闪帧”），点开定位。
6. **音频不可见**。至少显示 A 轨片段、静音状态和增益。
7. **撤销没有历史**。显示“可撤销 N 步”和最近一步的名称。

建议的实施顺序：1 → 2 → 5 → 3 → 4。1、2、5 都只需要客户端改动和已有接口，3、4 需要先在真实引擎上验证命令参数。

## 4. 0.4.0 修掉的缺陷（读代码发现）

1. `loadConfig` 用 `!isDir(cliPath)` 判断 CLI 是否丢失 —— 对任何可执行文件都为真，用户自定义的 CLI 路径会被默认安装路径悄悄覆盖。改为 `!isFile`。
2. README 写“导出永远串行”，但 `jobStart` 从不检查。现在已有导出在跑时拒绝新的导出。
3. 宿主重启后，正在导出的任务记录永远停在 running（orphan）。现在 pid 已不在就从日志结算；pid 还在就只在内存里估算进度，不写盘，避免覆盖真正所有者写的结果。
4. 批处理部分失败会留下半成品。`edit.write` 新增 `atomic`，MCP 默认开启。
5. 面板、宿主内置 `filmcraft_edit` 工具、MCP 三方可以同时写同一个 `.fcproj`，没有任何互斥。现在三者共用一把跨进程锁（`<工作区>/work/locks/`，死进程或 15 分钟后视为过期）。

## 5. 尚未验证 / 需要你在本机确认

- 所有测试都跑在**模拟 CLI**（`test/mock-filmcraft-cli.mjs`）上，证明的是 MCP 层的协议、时间换算、锁、快照、回滚和任务管理，**不是**真实引擎的行为。
- 真实引擎上的待验证项：`timeline.move` 一次多片段移动是否会互相覆盖（`reorder` 依赖它）；移动视频时联动音频是否跟随（之后用 `check_timeline` 看 link-desync）；`clip.enable` 确实是切换语义；`effects.reset` 是移除效果还是只重置参数（现有“清空调色”依赖它）。
- 验证方法：`set FILMCRAFT_CLI=...\filmcraft-cli.exe` 后执行 `node test/mcp-smoke.mjs --real D:\素材\a.mp4 D:\素材\b.mp4 D:\素材\c.mp4`。
